# Profile setup guide

This repository (`acharj1296/acharj1296`) is a special GitHub repository. Its `README.md` appears on your public profile at https://github.com/acharj1296.

## 1. Files in this repository

| Path | Purpose |
| --- | --- |
| `README.md` | Profile content (markdown + inline HTML). |
| `assets/header.svg` | Animated header with name, terminal panel, and glow. |
| `assets/typing.svg` | Custom looping typing animation (no external service). |
| `assets/terminal.svg` | Terminal-style introduction. |
| `assets/divider.svg` | Animated separator. Reuse between sections. |
| `assets/footer.svg` | Animated footer matching the header. |
| `assets/stats/*.svg` | Generated GitHub stats cards (overview, languages, streak, activity). |
| `scripts/generate-stats.mjs` | Zero-dependency generator for the stats cards. |
| `.github/workflows/profile-stats.yml` | Refreshes the stats cards daily using the built-in `GITHUB_TOKEN`. |

## 2. Upload and publish

1. Merge the branch `arena/b4f289c3-acharj1296` into `main` (open a pull request, review, and merge). The README and SVGs use absolute `raw.githubusercontent.com/.../main/...` URLs, so they show only after they are on `main`.
2. Open https://github.com/acharj1296 and confirm the README is shown.
3. Hard-refresh the page (Ctrl+F5 or Cmd+Shift+R). GitHub caches images, so changes can take a few minutes.
4. Optional: in the repository, go to Settings > Actions > General and confirm workflows are allowed. Then go to the Actions tab and run "Refresh profile stats" once with **Run workflow**.

No API keys, tokens, or secrets are needed. The stats workflow uses GitHub's built-in `GITHUB_TOKEN`.

## 3. Replace the placeholders

Search the repository for these tokens and replace them. Each one appears in `README.md`:

| Placeholder | Replace with | Example |
| --- | --- | --- |
| `YOUR_LINKEDIN_USERNAME` | Your LinkedIn profile slug | `jane-doe-123` |
| `YOUR_EMAIL_ADDRESS` | A contact email you want public | `you@example.com` |
| `YOUR_PORTFOLIO_URL` | Your portfolio domain, without `https://` | `yourname.dev` |

Remove any contact row you do not want to publish. Remove the matching badge in the badge row as well.

Other things to review:

- **Projects:** the table lists your three public repositories (MyMail, arena-ai-mailbox, Jarvis). Their descriptions were written from their README files. Edit them if they should be worded differently. Add more rows for new projects.
- **Areas I am exploring:** these were taken from the interests you listed. Edit them to match what you are actually learning.
- **About text:** only states what you told me. Add experience or achievements yourself if you want them shown.
- **Repository descriptions:** the three repositories have no GitHub descriptions yet. Adding them is optional but makes them clearer.

## 4. Stats cards and fallbacks

- The four cards in `assets/stats/` are plain SVG files committed to this repository, generated by `scripts/generate-stats.mjs` from the GitHub API. They do not depend on a third-party stats server.
- The workflow runs daily at 03:17 UTC and commits only when the numbers change.
- GitHub's own contribution graph is always shown on your profile page, so if any card fails to load the profile still shows activity.
- Public stats services such as the shared github-readme-stats Vercel instance were avoided on purpose. Their docs describe the public instance as best-effort, and it has returned errors during testing.
- Note: GitHub only counts a scheduled workflow's activity if the repository has other activity. If the workflow stops running after 60 days without repository activity, run it manually from the Actions tab.

To regenerate locally (optional):

```bash
GITHUB_TOKEN=<your token, read-only public access is enough> node scripts/generate-stats.mjs
```

Do not commit the token.

## 5. Technology icons

The icons come from skill-icons (https://skillicons.dev), a public service. If it is unavailable, the technology names remain in the text below the icon rows, so the list is still readable.

## 6. Customizing colors

All SVGs use the same palette:

- Background `#05050a`
- Purple `#a855f7`
- Cyan `#22d3ee`
- Green `#34d399`

To change the palette, edit the `stop-color` and `fill` values in the SVG files. In `scripts/generate-stats.mjs`, edit `LEVEL_COLORS`, `LANGUAGE_COLORS`, and the card colors.

## 8. Known limitations

- GitHub renders SVGs as images, so they cannot run JavaScript and cannot load web fonts. The SVGs use monospace and sans-serif system font stacks.
- Animations play inside `<img>` tags. They work in browsers that support SMIL and CSS animations in SVG images, which includes current Chrome, Edge, Firefox, and Safari.
- The technology icons from skill-icons are static images. The animated parts are the header, typing line, terminal, footer, and separator.
- No visitor counter is included. If you want one, a public counter such as Komarev's profile-views badge can be added as a single image line in `README.md`.
